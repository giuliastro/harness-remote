# Harness Remote 3.8.0

> **DeepSeek Harness joins Harness Remote.** Open its native Sessions from desktop, web or Android, choose models and reasoning levels, and keep working in the same Project.

### DeepSeek Harness

The new ACP integration discovers existing DeepSeek Sessions, replays their conversation, and supports prompts during a running turn. Model choices come from the harness, including provider-specific models and effort levels. DeepSeek now has its own icon in Session lists and chat. The adapter can use an installed `dsh-acp` or fetch the pinned package; the host needs Node.js 22.15+ and DeepSeek credentials. See the [setup notes](https://github.com/giuliastro/harness-remote/blob/main/docs/DEPENDENCIES.md#deepseek-harness-dsh--acp-over-stdio-via-a-third-party-adapter). [#629](https://github.com/giuliastro/harness-remote/pull/629), [#634](https://github.com/giuliastro/harness-remote/pull/634)

### Smoother Sessions

- Installed harnesses stay visible in Session pickers. PI and DeepSeek discovery and session reads recover correctly, and slow cold discovery gets a brief retry. [#628](https://github.com/giuliastro/harness-remote/pull/628), [#630](https://github.com/giuliastro/harness-remote/pull/630)
- Starting a prompt marks its Session active immediately; queued prompts leave the queue before they are sent. [#632](https://github.com/giuliastro/harness-remote/pull/632)
- The open Activity heading remains visible while scrolling the transcript, stays below the lineage panel, and shows the correct chevron state. [#633](https://github.com/giuliastro/harness-remote/pull/633)
- ACP adapters started through `npx` handle Windows paths safely, and cross-agent handoff stays inside the Session's Project. [#628](https://github.com/giuliastro/harness-remote/pull/628)

### Plugin isolation

Gateway credentials are no longer passed to plugin processes. [#627](https://github.com/giuliastro/harness-remote/pull/627)
