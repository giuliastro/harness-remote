# Harness Remote 3.9.0

> **Notifications that reach you wherever you are.** Android keeps your machines connected in the background, desktop keeps listening from the tray, and the web app can notify you too. You hear when a Session needs you, finishes or fails, and on Android you can allow or deny a permission straight from the notification.

### Android background notifications

- A foreground service keeps an authenticated connection to every paired machine while the app is in the background, independent of the WebView. Its ongoing notification shows the connection state and has a **Stop** action. [#654](https://github.com/giuliastro/harness-remote/pull/654), [#656](https://github.com/giuliastro/harness-remote/pull/656)
- Permission and question requests arrive as notifications that open the exact Session. Permission notifications offer **Allow once** and **Deny**, answered without opening the app. [#655](https://github.com/giuliastro/harness-remote/pull/655), [#659](https://github.com/giuliastro/harness-remote/pull/659)
- **Ready** and **Failed** notifications tell you when a turn ends. Only a turn the service saw working can post Ready, and the Session already on screen is not notified twice. [#657](https://github.com/giuliastro/harness-remote/pull/657), [#658](https://github.com/giuliastro/harness-remote/pull/658), [#664](https://github.com/giuliastro/harness-remote/pull/664), [#666](https://github.com/giuliastro/harness-remote/pull/666)
- After an update the app asks again for notification permission when it needs it. Tapping a notification no longer reloads the app. Settings can restore a hidden connection notification and links to battery guidance for stricter phone makers. [#661](https://github.com/giuliastro/harness-remote/pull/661), [#663](https://github.com/giuliastro/harness-remote/pull/663), [#665](https://github.com/giuliastro/harness-remote/pull/665), [#667](https://github.com/giuliastro/harness-remote/pull/667)
- A machine that drops off the network no longer posts an alert of its own; the connection state stays in the app and in the ongoing notification. [#673](https://github.com/giuliastro/harness-remote/pull/673)

### Desktop and web notifications

- Closing the desktop window now keeps Harness Remote in the system tray, so the embedded daemon and notifications keep running. The tray menu opens the app or quits it. [#660](https://github.com/giuliastro/harness-remote/pull/660)
- Desktop and web notify when a Session is ready, fails or needs your attention, for every harness. Each device has its own notification settings. [#669](https://github.com/giuliastro/harness-remote/pull/669)
- A Session that finished while you were elsewhere counts under **Attention** until you open it. [#646](https://github.com/giuliastro/harness-remote/pull/646)

### Faster, clearer Session loading

- The browser shares one live connection per machine, so a machine with many harnesses no longer leaves the Session list waiting for minutes. [#671](https://github.com/giuliastro/harness-remote/pull/671), [#675](https://github.com/giuliastro/harness-remote/pull/675)
- While Sessions load, each machine shows a single card listing the harnesses still starting or retrying, on phone, web and desktop. [#667](https://github.com/giuliastro/harness-remote/pull/667), [#673](https://github.com/giuliastro/harness-remote/pull/673), [#674](https://github.com/giuliastro/harness-remote/pull/674), [#677](https://github.com/giuliastro/harness-remote/pull/677)
- Harnesses installed in your user directories, such as `~/.local/bin` or `%APPDATA%\npm`, are found even when the desktop app starts with a shorter PATH than your shell. [#674](https://github.com/giuliastro/harness-remote/pull/674)
- An open Session keeps updating when the same Session is continued from another device. [#668](https://github.com/giuliastro/harness-remote/pull/668)

### Fixes

- Prompts with Chinese, Japanese, emoji or accented text are no longer corrupted when a long request arrives in pieces. [#676](https://github.com/giuliastro/harness-remote/pull/676)
- Active ACP turns keep running while the desktop app is idle, and idle unload waits for pending ACP requests. [#639](https://github.com/giuliastro/harness-remote/pull/639), [#641](https://github.com/giuliastro/harness-remote/pull/641)
- A failed model discovery no longer breaks callers that do not wait for it. [#640](https://github.com/giuliastro/harness-remote/pull/640)
- Replayed transcripts pair replies correctly and load faster for long Sessions. [#636](https://github.com/giuliastro/harness-remote/pull/636), [#637](https://github.com/giuliastro/harness-remote/pull/637)
- DeepSeek starts reliably after an incomplete `npx` cache or a slow cold start, and a tool turn's reply is drawn once. [#642](https://github.com/giuliastro/harness-remote/pull/642), [#643](https://github.com/giuliastro/harness-remote/pull/643), [#670](https://github.com/giuliastro/harness-remote/pull/670)
- The phone composer keeps its controls below the draft instead of over it. [#663](https://github.com/giuliastro/harness-remote/pull/663)
